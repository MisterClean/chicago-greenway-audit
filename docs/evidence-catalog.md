# Evidence catalog

`data/routes/review-evidence.json` is the authoritative editable input. Run `node scripts/build-evidence-catalog.mjs` from the repository root to compile deterministic JSON files in `data/routes/` and `public/routes/`. Run it with `--check` to fail if either output is missing or stale. `node --test scripts/evidence-catalog.test.mjs` runs the focused tests. The compiler does not retrieve or verify linked documents.

`compileEvidenceCatalog(evidence)` returns the catalog. `validateEvidenceCatalog(catalog)` reconstructs the complete derived catalog from `raw_evidence` and compares it with the supplied catalog, detecting dropped observations and changes to any derived field, including sources, citations, bindings and search gaps. It validates the input's IDs, URLs, hashes, dates and geographic bindings while rebuilding. This establishes internal consistency, not independent authenticity: a wholesale coherent replacement of both raw and derived data requires comparison against the authoritative input or the CLI stale check.

`canonicalSourceUrl` normalizes an HTTP(S) URL and removes its fragment; the ID is `source-` followed by the full SHA-256 of that canonical URL. Query strings remain part of the identity. Citation URLs retain fragments. Identity does not assert that different URLs represent different real-world documents, or that every citation to one URL describes the same revision.

Each observation retains the input record ID, location, movement, claim and review context, original record, and city-row and OSM-way bindings. Optional `way_segments` bind a positive way ID to an ordered list of at least two positive node IDs; this validates identifiers and order as supplied, not their existence, geometry or movement permission. An optional gap bounding box is retained. `geographic_scope_missing` flags absence of a location and all supported bindings; having a scope is not evidence that it is precise or correct.

Each citation retains normalized explicit title, publisher, source type, source date and date kind, scope, status, page references, hash, retrieval date, review method and the entire raw citation. `pdf_pages` is accepted as an alias when `pages` is absent. Dates are not merged into a source: different citations may refer to different dates, versions, or hashes. Dates accept ISO year, year-month, calendar date, or a timestamp with seconds and timezone; impossible dates are rejected. A date's meaning comes from `date_kind`, not its format. `evidence_kind` is a conservative classification of the citation's own status/date description; a design or proposal is not an as-built finding.

For title, publisher and source type, each canonical source lists every distinct explicitly supplied value in `metadata_variants` with its evidence ID and zero-based citation index. The corresponding canonical value is populated only when exactly one distinct value was supplied; conflicts remain null and are flagged `conflicting`. No titles, publishers or dates are inferred. `metadata_gaps` identifies missing citation details, including page and hash when absent; this is a completeness indicator, not a requirement that HTML or any other source have a PDF page or hash. Source-level gaps identify absent title, publisher and type. Missing details are not negative findings.

`search_gaps` indexes top-level and record-level fields named with `search_gap` or `search_attempt`, preserving their values and recording a null evidence ID for top-level fields. Other uncertainty and review needs remain in each observation and the complete raw input. All raw data remain intact, including extra fields and different versions of the same URL.

`content_fingerprint` identifies what the checksum covers. When a citation provides `snapshot_url`, the checksum belongs to that saved extract, not the live OSM object page. Otherwise it identifies the retrieved document or dataset response. The original checksum and citation metadata remain intact.

`npm run data:routes` rebuilds both catalogs with the route export. Use `npm run data:evidence` for an evidence-only update and `npm run verify:evidence` to check freshness. The production build requires current catalogs. The app links the downloadable catalog from Sources & method. Research-batch metadata and record IDs are retained in the editable input, alongside the per-source observations.
